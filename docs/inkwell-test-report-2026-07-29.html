Release-readiness test | 29 July 2026

Inkwell works, but it is not Grammarly-level yet

A real installed-extension test against Craig's local Ollama found a solid proofreading core, several hard browser cases that already work, and release blockers in accuracy, failure handling, accessibility, cross-frame state and abuse resistance.

Verdict: alpha-quality, not ready for a Grammarly parity claim The normal flow works in textareas, text inputs, rich text, controlled fields, dynamic fields, open shadow roots and cross-origin frames. The current local-model results are too inconsistent for trusted daily proofreading, and the product is missing a large part of Grammarly's browser feature set.

Local-model quality

A browser extension can be mechanically correct and still be a poor proofreader. These results use the extension's exact prompt, schema, background worker and Ollama connection.

Qwen was usually responsive once warm. Gemma took roughly two minutes for eight small cases and failed half of them, despite “Save and test” saying it was connected.

Recommendation: keep the local LLM for contextual grammar, clarity and rewrites, but add a deterministic local spelling and rule layer. A 7B model on its own is not consistent enough to match a mature proofreader. Build a fixed acceptance corpus and qualify each model before it can be selected as “recommended”.

Release blockers

High Current model path is not accurate enough for trusted proofreading

lib/checker/prompt.ts, lib/checker/schema.ts:205-227, entrypoints/options/main.ts:183-235

What's wrong: Qwen misses clear errors, misclassifies categories, creates unsafe replacements and follows instructions inside the passage. Gemma passes the connection test but frequently returns unusable output.

Why it matters: a proofreader that silently misses mistakes or offers corrupt edits breaks the product's main promise.

Fix: make connection testing perform a small structured completion, add a model qualification suite, reject changes to emails, URLs and code-like tokens, and use a local spelling and grammar rule layer before the LLM.

High Short fields are never checked

lib/checker/chunker.ts:10-12, 50-63

What's wrong: every chunk under 12 characters is skipped. The live teh test generated no request.

Why it matters: titles, short replies, search terms and single-word typos are common browser-extension use cases.

Fix: remove the length threshold or reduce it to a letter-aware minimum. Cover teh, recieve and short clean words in regression tests.

High Settings changes leave stale advice on screen

entrypoints/content.ts:27-46, lib/content/fieldController.ts:153-177, 205-214

What's wrong: the content script reacts only to global and site enablement. It does not clear field caches when model, dialect, strictness or categories change.

Why it matters: users can disable a rule and still see its underlines, or keep advice from the wrong dialect and model.

Fix: give controllers a settings version. On any checking-setting change, cancel pending work, clear cached results, rerender and recheck the active field.

High Web-page failures look like clean writing

lib/content/fieldController.ts:217-235, entrypoints/popup/main.ts:45-61

What's wrong: an in-page network or model failure produces no visible editor state. The only evidence is a console warning, while the popup can still say there are no suggestions.

Why it matters: users cannot tell “no errors” from “nothing was checked”.

Fix: add per-frame status to the message protocol and badge/popup. Show checking, checked, partial and failed states beside the active field, using the honest-state pattern already present in the dashboard.

High Request IDs collide across tabs and frames

lib/content/fieldController.ts:30, 208, lib/checker/service.ts:47-50, 102-110

What's wrong: each isolated content-script frame starts the same counter. The background's global active map is keyed only by that local ID.

Why it matters: one frame can overwrite or cancel another request, break the two-request limit, or lose a result. Gmail-style iframe use makes this realistic.

Fix: generate IDs with crypto.randomUUID(), or scope them by port, tab and frame before inserting them into the background map.

High Security: an enabled page can drive and read the model

lib/content/editableWatcher.ts:47-67, lib/content/fieldController.ts:71-77, lib/content/overlay/host.ts:128-144 | OWASP LLM01 and LLM10

Source to sink: page-generated focus and input events reach the provider, then model output is exposed through an open shadow root.

What's wrong: the test page triggered an Ollama request with no user gesture and read the resulting suggestion. Qwen also followed an instruction embedded in the passage.

Why it matters: a malicious site can use the extension as a constrained LLM oracle and repeatedly consume local compute or paid cloud quota. The human Apply gate limits the edit impact, but not the request or read.

Fix: require a recent trusted pointer or keyboard interaction before starting checks, add per-origin rate and text budgets, keep cloud checking opt-in by site, and expose the overlay through a closed shadow root. Treat prompt delimiters as defence in depth, not a security boundary.

High Suggestions cannot be used with a keyboard or screen reader

lib/content/overlay/underlines.ts, lib/content/overlay/card.ts

What's wrong: underlines are div elements with tabIndex=-1, no role and no accessible name. The card can only be opened with a pointer.

Why it matters: keyboard and assistive-technology users cannot review or apply suggestions. This fails the browser-extension parity baseline and WCAG keyboard access.

Fix: add a keyboard shortcut and ordered review panel, provide focusable controls with names and states, support Escape, Tab, Enter and Space, and add Playwright plus axe coverage.

High The document workspace bypasses chunking

entrypoints/dashboard/main.ts:221-259, lib/checker/service.ts:141-149

What's wrong: the dashboard sends the full document in one model request, unlike the page checker.

Why it matters: a large import can exceed a local model's context, time out, or return only an early subset of findings. Superseded checks also continue using compute.

Fix: chunk documents, merge offsets and partial results, cancel the previous request as soon as the text changes, and show progress by chunk.

High No durable installed-extension E2E suite exists

package.json, TEST_INFRA.md, tests/dashboard.e2e.test.ts

What's wrong: the repository's “E2E” tests run in Happy DOM with mocked Chrome APIs. No checked-in test loads the extension, focuses a real field or exercises CORS, frames, underlines and Apply.

Why it matters: the exact bugs found in this review can regress while all 188 tests stay green.

Fix: add a Playwright persistent-context suite for the built extension. Keep the Ollama cases opt-in locally, and run deterministic fake-provider browser cases in CI.

Other issues

  • Medium Shadow-root focus-out compares the retargeted e.target with the inner field at lib/content/editableWatcher.ts:69-74. Use composedPath() on blur too.
  • Medium Badge counts are stale and represent the last active field in each frame, not the page. Report zero on deactivate and define whether the badge means active field or full page.
  • Medium about:blank and srcdoc iframe editors are not covered because the content script has no match-about-blank or origin-fallback setting.
  • Medium Results after the first 20 are silently truncated at lib/checker/schema.ts:213. Count the overflow as dropped and page or chunk the results.
  • Medium The capitalisation repair at lib/checker/anchor.ts:105-112, 202 can uppercase a legitimate mid-sentence replacement. Apply it only after a case-insensitive fallback at a sentence boundary.
  • Medium API keys live in chrome.storage.local, which content-script contexts can read directly. Set storage access to trusted contexts and expose only non-secret settings through background messages.
  • Medium A remote OpenAI-compatible endpoint can be labelled “local”, and plaintext HTTP is allowed outside loopback. Warn when data leaves the device and require HTTPS for non-loopback hosts.
  • Medium Sensitive-field checks cover passwords, card autocomplete and OTP, but not address fields, usernames, code editors or spellcheck="false". Expand the deny rules and provide site-level privacy controls.
  • Low Cloud API origins are granted at install time at wxt.config.ts:11-18, even for local-only users. Keep loopback static and request each cloud origin only when selected.
  • Low .gitignore covers environment files but not *.pem, *.key or credentials*.json. No such secret file is currently tracked.
  • Low PDF lazy loading is ineffective because lib/import/index.ts imports PdfError statically and the PDF module dynamically. Both builds warn about it.
  • Low TEST_INFRA.md calls the mocked Happy DOM suite “Complete 4-tier E2E”. Rename it to simulated integration coverage.

Recommended order of work

  1. Make failure honest. Add visible checking, partial and failed states to ordinary web fields and the popup.
  2. Fix correctness races. Use globally unique request IDs, invalidate caches on settings changes, fix shadow blur and reset badge counts.
  3. Build a real browser test gate. Check textarea, input, contenteditable, controlled fields, frames, shadow DOM, Apply, undo, failure and settings changes.
  4. Harden the page boundary. Require recent user interaction, rate-limit each origin, close the shadow root and lock extension storage to trusted contexts.
  5. Raise proofreading quality. Add deterministic local spelling and grammar checks, plus a model acceptance corpus covering false positives and injection.
  6. Close core parity gaps. Keyboard review, personal dictionary, ignore-all, more dialects, better clarity and tone, then rewrites.
Release call Safe enough for supervised personal testing with qwen2.5:7b-instruct, after selecting that model in settings. Not ready to market as working everywhere, not ready for cloud-provider use on arbitrary sites, and not close enough to Grammarly to claim feature parity.
