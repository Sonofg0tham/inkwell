Inkwell v0.1.1 test and Grammarly parity report

A clean-install, real-model and installed-browser review of the local-LLM proofreading extension.

Verdict: ready for supervised personal Chrome use, but nowhere near full Grammarly parity. The core proofreading path is real and substantially stronger than v0.1.0. It works with the recommended local Qwen model across the main editable DOM patterns. The missing languages, browsers, Google Docs integration, tone tools and broader writing suite still rule out a Grammarly-equivalent claim.

What passed

  • npm.cmd ci, TypeScript, all production builds and the v0.1.1 ZIP completed successfully.
  • Vitest passed 34 files and 423 tests. Six opt-in multi-model probes were skipped because INKWELL_PROBE was not set. The live Ollama suite did run.
  • qwen2.5:7b-instruct passed four independent qualification calls covering spelling, grammar, punctuation, clean text with a prompt-injection attempt, and a Picky-mode style correction.
  • The installed extension applied a model-only grammar correction in an input, textarea, flat and nested contenteditable editor, controlled field, dynamically added field, open shadow root, same-origin srcdoc frame and cross-origin frame.
  • Nested rich-text formatting survived Apply. Disabling the top-level site also stopped checking inside its cross-origin child frame.
  • The installed extension imported a real one-page PDF through the packaged legacy PDF.js worker, and a large local-model workspace check paused after 60 chunks for explicit continuation.
  • The generated manifest is version 0.1.1, requires Chrome or Edge 119+, injects into all frames with origin fallback, and keeps required host access to loopback providers only. Remote HTTPS providers remain optional permissions.
  • The exact ZIP contains 33 entries and 28 files. It has no tests, traces, environment files or source maps. Every extracted file matched the production build by SHA-256.
  • The Chrome Web Store icon, promotional tile and three screenshots were regenerated, dimension-checked and visually reviewed at desktop and mobile widths.

What is still unproven

  • No logged-in manual run was completed on Gmail, Slack, Notion, Word Online, Reddit or other named third-party products. The browser fixture covers their common DOM patterns, not every product's private implementation or future redesigns.
  • Chrome was the only browser exercised as a live installed extension. The Edge result is a production build check, not a separate runtime session.
  • data:, blob: and filesystem: origin-fallback injection is present in the manifest but was not exercised as a real opaque-frame Apply flow.
  • Closed shadow-root fields remain inaccessible by browser design. Inkwell's own overlay uses a closed shadow root, which the test reaches through Chrome DevTools only for verification.
  • Model behaviour can drift. The qualification gate catches obvious unsuitability, but it cannot make every local or cloud model as consistent as a centrally managed commercial service.
Release advice: retire the v0.1.0 prerelease once v0.1.1 clears pull-request CI. Market v0.1.1 as a private, local-first Chromium proofreading beta. Do not call it a Grammarly replacement or say it works everywhere.
